# Using the Delivery Analysis Workbook

The portfolio workbook uses validated aggregate outputs from `data/processed/`. This file does not contain customer IDs, order-level transactions, review text, or external workbook links.

## Reading the results

Start with `KPI Summary`. Its order counts sum the monthly analysis, and its rates divide late or on-time orders by eligible delivered orders. The reconciliation block compares these results with the independently aggregated SQL summary. Rate checks use the same two-decimal percentage precision as the SQL output.

`Monthly Delivery` retains all 23 purchase-month cohorts. Its chart uses January 2017-August 2018 because the 2016 cohorts are sparse. `Vs overall (pp)` measures the difference from the overall rate in percentage points. Total rates use total counts, not an average of monthly percentages.

`Regional Performance` contains all 27 customer destination codes. Filterable columns retain counts alongside rates. Highlighting identifies rates above the overall baseline; it is not a statistical significance test or a confirmed operational priority.

`Customer Satisfaction` keeps the full selected-review sample separate from reviews answered on or after receipt. The samples overlap. Mean ratings are imported SQL results, and Excel calculates low-rating percentages from the corresponding counts. Do not average the rounded means to construct a new overall rating.

`Data Dictionary` records field definitions, source ownership, calculation rules, and refresh limitations. Teal text identifies Excel formulas. Counts and mean scores imported from SQL remain ordinary input values.

## Refreshing the workbook

Run `python scripts/run_pipeline.py` first. Update the monthly and regional input columns C:G using the matching exported records, preserving column B's group labels and the Excel formulas. If the group list changes, extend the table, formulas, chart references, and summary ranges together.

For customer reviews, update columns C:E in the two sample blocks using the matching sample and delivery status. Preserve the formulas in column F. Update the duration values in `KPI Summary!C14:C15` from `delivery_duration.csv` and the SQL reference controls in column I from `delivery_summary.csv`.

Review the written findings after changing data. They describe the saved snapshot and are not generated by formulas. Recalculate and save in Excel, then run:

```bash
python scripts/validate_workbook.py
```

The validator checks the saved workbook against the aggregate outputs, including formula caches, dates, sample sizes, rates, native chart bindings, and filters. It does not launch or test Microsoft Excel. The analysis pipeline refreshes aggregate files; it does not automatically overwrite this workbook.
